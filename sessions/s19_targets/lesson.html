Something To Shoot

There are targets on screen now, drifting along the top. Your shots go straight through them, which is not much of a game.

What you're making

Seven targets that bounce along the top of the screen and vanish when you hit them, taking the shot with them.

The four checks you wrote in Session 14 finally get a job.

New this session

Things need to know their own size. Back in Session 14 every box was BOX_SIZE across, so the checking function could just use that. A shot is 4 wide and a target is 44, so that will not do any more — each one carries its own w and h, and the checks read those instead.

Which makes overlaps work on anything. Shot against target, ship against target, anything against anything — as long as both have an x, a y, a w and an h, the same function answers.

And a hit removes two things at once. You cannot take either of them out of its list while you are looping, so mark them first and clear them out afterwards — the same "keep the ones you want" pattern as last session, run twice.

Stuck?

Hint 1 — why mark them instead of removing them?

Because you are inside two loops, both walking lists, and taking something out of either one mid-walk is the bug from last session — twice over.

So the job splits in two. First pass: find out what got hit, and write it down on the thing itself. Second pass: build the lists again without them.

That "decide first, act afterwards" shape turns up constantly once games get bigger. It is nearly always the way out of "I cannot change this while I am looking at it".

Hint 2 — what does "hit" not in shot mean?

It asks whether that dict has a key called "hit" at all.

Shots are built without one. The only way a shot gets a "hit" is if the collision code put it there — so its presence is the mark. No key means it survived.

You could equally give every shot "hit": False when it is made and check if not shot["hit"]:. Both are fine. The second is probably tidier; the first is less typing.

Hint 3 — one shot is killing several targets
If a shot is wide enough, or targets are overlapping each other, one shot can be on top of two at once and both get marked. That is a real choice, not a bug — if you would rather one shot only ever took one target, stop checking that shot as soon as it hits something.

# state.py

def overlaps(a, b):
    if a["x"] + a["w"] < b["x"]:
        return False
    if b["x"] + b["w"] < a["x"]:
        return False
    if a["y"] + a["h"] < b["y"]:
        return False
    if b["y"] + b["h"] < a["y"]:
        return False
    return True


# main.py, in the game loop

    for shot in shots:
        for target in targets:
            if overlaps(shot, target):
                shot["hit"] = True

    kept_shots = []
    for shot in shots:
        if "hit" not in shot:

    shots = kept_shots

    for target in targets:
        if "hit" not in target:
            kept_targets.append(target)
    targets = kept_targets
