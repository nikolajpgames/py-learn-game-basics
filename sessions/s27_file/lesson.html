Levels From A File

So far the shape of the wall has been decided by a loop. From now on it is decided by a text file you can open in Notepad.

What you're making

A level drawn as characters in a text file, and a loader that turns it into bricks.

Change the file, save, run. No Python touched at all.

New this session

open gives you a file to read. Looping over it hands you one line at a time, in order, as text.

A line of text can be looked at character by character, exactly like a list. line[0] is the first character, line[3] the fourth — counting from zero, as always.

So the file is the grid. Which line you are on is the row; how far along that line you are is the column. The nested loop from Session 23 does not change at all — it just asks the text what belongs at each square instead of filling every one.

Geometry Dash levels work exactly this way too — the same nested loop, reading different characters out of a different file.

Stuck?

Hint 1 — what is the with in "with open"?

It means "open this, let me use it, and close it properly afterwards even if something goes wrong".

You can open a file without it, but then you have to remember to close it, and a file left open can lose what you wrote to it. with makes that impossible to forget, so it is what everyone uses.

Hint 2 — what is rstrip doing?

Every line in a text file ends with an invisible newline character, which is what makes the next line start. When you read a line, that character comes along with it.

So ".........." arrives as eleven characters, not ten, and the last one is invisible. rstrip("\\n") takes it off the right-hand end.

Leave it in and you get a phantom column that never becomes a brick — harmless here, and confusing the moment you count anything.

Hint 3 — two square brackets in a row?

rows[row] picks one line out of the list — a piece of text. rows[row][col] then picks one character out of that.

Left to right, one step at a time. Same as stars[0][1] would have been back in Session 9.

def load_level(filename):
    bricks = []
    rows = []

    with open(filename) as f:
        for line in f:
            line = line.rstrip("\\n")
            if line != "":
                rows.append(line)

    for row in range(len(rows)):
        for col in range(len(rows[row])):
            if rows[row][col] == "#":
                brick = {
                    "x": BRICK_LEFT + col * (BRICK_W + BRICK_GAP),
                    "y": BRICK_TOP + row * (BRICK_H + BRICK_GAP),
                    "w": BRICK_W,
                    "h": BRICK_H,
                    "colour": BRICK_COLOURS[row % len(BRICK_COLOURS)],
                }
                bricks.append(brick)

    return bricks

Challenge

Use different characters for different bricks. A # for a normal one, an X for one that takes two hits, a * for one worth double points.

The loader already looks at the character — it just only asks one question about it. Ask two or three instead, and put the answer in the brick's dict.

Then let the file choose its own colours. Digits 1 to 5 picking out of BRICK_COLOURS, so a level can be striped, or spell something in colour. int(character) turns a digit-character into a number.

How it could break

FileNotFoundError: level01.txt The file is not in the same folder as main.py, or the name has a typo. Windows sometimes hides the .txt, so level01.txt.txt is a real possibility.
The wall is one column wider than the file looks The rstrip is missing, so the invisible newline is being counted as a column.
IndexError: string index out of range The lines are not all the same length — a short one has fewer columns than you are asking for. Using len(rows[row]) rather than a fixed number avoids this entirely.
Only the first row of bricks appears return bricks is inside a loop again. It belongs at the very end of the function.
Nothing appears at all Either the file has no hashes in it, or the check is looking for a different character than the file contains. Print the rows list and see what actually arrived.
The bricks are in one column down the left The x sum is not using col. Compare it against Session 23's.
