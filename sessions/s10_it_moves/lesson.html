Session 10 Arc 2 · Motion & Time

It Moves

Everything so far has sat perfectly still. Today it stops doing that.

What you're making

A box that slides across the window. It'll run straight off the edge and never come back — that's expected, and you'll fix it in Session 12.

It also picks up the two halves every game is built from: one that works out what happens next, and one that draws it.

New this session

A function is a named set of instructions you can run whenever you like. def update(x, y): makes one called update. Writing update(box_x, box_y) further down runs it.

There are two functions in this file and they have completely different jobs.

update changes the state of the game — where everything is, how fast it is going, what has bumped into what. It moves the world on by one step and touches nothing you can see.

draw takes that state and paints one frame of it — a single picture of how the world looks right now — onto the screen. It only reads the state — it never changes it.

Neither one does the other's job. Ever.

That sounds fussy right now, with one box. By the time there's a player, spikes, music and a level, it's the thing that stops the whole program turning into spaghetti. Real games are built exactly like this.

Stuck?

Hint 1 — how do I make it go diagonally?
update already has y handed to it, and already hands it back. All that's missing is a line that changes it on the way through — the same shape as the line that changes x.
Hint 2 — what does "return" mean?

update works on its own private copies of x and y. Changing them inside doesn't touch box_x and box_y outside — so at the end it returns them, and the line that called it catches them:

box_x, box_y = update(box_x, box_y)

Delete that box_x, box_y = at the front and the box stops moving. Try it, then put it back.

Show me a finished version 
# diagonal, down and to the right

STEP_X = 4
STEP_Y = 2


def update(x, y):
    x = x + STEP_X
    y = y + STEP_Y
    return x, y

Challenge

Send it corner to corner. Make the box start at the bottom-left of the window and travel exactly to the top-right, leaving the screen right at the corner.

You'll need to think about what y has to do to go up, and you'll need the two step sizes to be in the right proportion to each other. Getting it dead-on is properly satisfying.

How it could break

The box leaves a smear behind it like a paint roller screen.fill(BG) got deleted from draw. Without it you're painting on top of the last frame instead of starting clean. Worth looking at for a second before you fix it — that smear is every frame you've drawn so far.
Nothing moves at all The result of update isn't being caught. The line needs to be box_x, box_y = update(box_x, box_y) — with the catching part at the front.
TypeError: update() takes 2 positional arguments but 3 were given You're handing update more things than it has slots for. The brackets on the def line and the brackets where you call it have to match.
NameError: name 'STEP_Y' is not defined You used it before you made it. Python reads top to bottom — it has to exist above the line that uses it.
The box vanishes instantly STEP is enormous, so it crosses the whole window in one or two frames. Not broken, just very fast.
