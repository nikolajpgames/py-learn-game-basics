Doing It Again

Computers are not clever, but they are extremely patient. Today you put that to work.

What you're making

Two counters. One counts up because it was told exactly how many times, the other counts down until a condition stops being true.

The second kind is the one every game is built on. When you open a window in Session 6, it stays open because of a loop just like it.

New this session

for repeats a known number of times. for i in range(5): means "do the indented lines five times", and i holds a different number each go.

while repeats as long as something stays true. It asks its question before every single go round, and the moment the answer is no, it stops.

Both use the same indent rule as if: what's pushed in is inside the loop, what isn't, isn't. That rule now covers everything.

Turn the knobs

One of these can hang your program. That's step 6, and it's on purpose.

range(5)How many times round. range(1) goes once. range(0) doesn't go at all — try it, the loop just gets skipped.
countdown = 3Where the while loop starts. Set it to 0 and the loop body never runs once, because the question is already no.
countdown - 1How fast it heads for the exit. Change it to - 2 and it skips numbers. Change it to + 1 and it runs forever.
Ctrl+CNot code — hold Ctrl and press C in the black window to stop a program that won't stop itself. Worth knowing by heart.

Stuck?

Hint 1 — what is i, and why does it start at 0?

i is just a variable, like score. The loop makes it for you and puts a different number in it each time round.

range(5) gives 0, 1, 2, 3, 4. That's five numbers, but it stops before 5. It looks wrong and there's a good reason for it, which will make sense the first time you count through a list.

Hint 2 — why did deleting one line make it run forever?

A while loop checks its question before every go. while countdown > 0 asks: is countdown bigger than zero?

The line you deleted was the only thing making countdown smaller. Without it, countdown stays at 3 forever, the answer is always yes, and the loop never gets to stop.

Every while loop needs something inside it that eventually makes the answer no. Forgetting that is the classic way to hang a program — and now you've done it on purpose, so it'll be familiar when you do it by accident.

Hint 3 — which loop should I use?
If you know the number in advance — 200 stars, 5 lives, every brick in a wall — use for. If you're waiting for something to happen and don't know how long — until the player quits, until the ball goes off screen — use while.
Show me a finished version 
# the seven times table
for i in range(13):
    print(i, "x 7 =", i * 7)

print()

# halve it until it gets small
number = 1000

while number > 1:
    print(number)
    number = number / 2

print("Done.")

Challenge

Build a pyramid. Get the output to look like this, using one loop:

*
**
***
****
*****

There is more than one way to do this and none of them is the right one. Here are two worth knowing:

Repeat the text. "*" * 3 gives you "***" — multiplying a piece of text repeats it. Short and neat, though it is more of a Python party trick than something you will reach for often.

Or build it up as you go. Start with nothing and add one more each time round:

stars = "**"
stars = stars + "*"     # stars is now "***"

That is the same shape as score = score + 100 from Session 2 — work out the right-hand side, put the answer back in the box. Growing something a piece at a time inside a loop is one of the most useful patterns there is, and it works in every language, so this is the one worth really understanding.

Pick whichever makes more sense to you and get it working. Then make it upside down. Then, if you are feeling mean to yourself, centre it into a proper triangle.

How it could break

It runs forever and won't stop Nothing inside the while is moving it towards the exit. Press Ctrl+C, then look for what should be changing each go.
The loop only prints one thing The line you wanted repeated isn't indented, so it sits outside the loop and runs once at the end.
It printed one fewer than expected range(5) stops before 5. If you want 1 to 5, use range(1, 6).
IndentationError: expected an indented block A for or while line with nothing pushed in underneath it. A loop has to have something to repeat.
SyntaxError: expected ':' Missing colon at the end of the for or while line. Same rule as if.
NameError: name 'i' is not defined Usually just a typo in the name. Worth knowing though: i does survive after the loop ends, holding whatever it had on the last go. You only get this error if the loop never ran at all — range(0) — so i was never made.

Stop while it still runs.
