Fifty Bouncers

One box needed four separate names. Fifty boxes would need two hundred. You already know how this gets fixed — you did it to the stars.

What you're making

Fifty boxes bouncing around at once, all from the same handful of lines that currently move one.

You will add the second one by hand first, which is the last time you will want to do that.

New this session

A dict keeps several named values in one thing. box = {"x": 100, "y": 60} — curly brackets, and each value has a name rather than a position. You get at them with box["x"] instead of box[0], which is a lot easier to read when there are four of them.

And unlike a tuple, a dict can be changed. That is the whole reason for using one here. A bouncing box moves sixty times a second, and a tuple is locked the moment it is made — so a tuple simply cannot do this job.

Which changes what happens when you hand one to a function. Session 5 showed you a number going in as a copy, with changes staying inside. A dict does not work like that, and the picture below is why.

Stuck?

Hint 1 — why did the second box eat the first one?

draw starts with screen.fill(BG), which paints over the whole window.

So the order was: clear, draw box one, clear again, draw box two. The first box was wiped out a fraction of a millisecond after it appeared.

Clearing the screen is a once-per-frame job, not a once-per-box job. It belongs in the game loop, above the drawing.

Hint 2 — dict, tuple or list?

All three hold several things. They differ in how you get at them and whether they can change.

(100, 60) — a tuple. By position, and locked forever.

[100, 60] — a list. By position, and it can change and grow.

{"x": 100, "y": 60} — a dict. By name, and it can change.

A bouncer needs to change, which rules out the tuple. And it has four different things in it rather than a row of the same thing, so names beat positions — box["vy"] tells you what it is; box[3] makes you go and count.

Hint 3 — why does update work with no return?

Because update is not given a copy of the box. It is given the box.

When you call update(box, dt), the name box inside the function and the name box outside are two labels stuck on the same dict. Change what is inside it and there is nothing to hand back — the change has already happened, everywhere.

That is the difference from Session 5, where score was a plain number and the function really did get its own copy. Numbers, text and tuples travel as copies. Lists and dicts travel as themselves.

def update(box, dt):
    box["x"] = box["x"] + box["vx"] * dt
    box["y"] = box["y"] + box["vy"] * dt

    if box["x"] < 0:
        box["vx"] = -box["vx"]
    if box["x"] + BOX_SIZE > WIDTH:
        box["vx"] = -box["vx"]
    if box["y"] < 0:
        box["vy"] = -box["vy"]
    if box["y"] + BOX_SIZE > HEIGHT:
        box["vy"] = -box["vy"]


# build them, above the game loop
boxes = []

for i in range(BOX_COUNT):
    box = {
        "x": float(random.randint(0, WIDTH - BOX_SIZE)),
        "y": float(random.randint(0, HEIGHT - BOX_SIZE)),
        "vx": random.choice([-SPEED, SPEED]),
        "vy": random.choice([-SPEED, SPEED]),
    }
    boxes.append(box)


# ... and inside the game loop

    for box in boxes:
        update(box, dt)

    screen.fill(BG)

    for box in boxes:
        draw(screen, box)

Challenge

Give every box its own colour. A dict can hold anything, so put one more thing in it when you build it — a colour is just three numbers, and you already know how to pick random ones.

Then use it in draw instead of BOX_COLOUR.

If that lands easily: give each one its own size as well, and make the wall checks use box["size"] rather than the setting at the top. That is the moment a box stops being "the box" and becomes properly its own thing.

How it could break

All fifty boxes move as one, perfectly on top of each other You built one dict above the loop and appended that same dict fifty times. Fifty labels, one box. The dict has to be made inside the loop so each go makes a fresh one — which is the diagram above biting you for real.
KeyError: 'X' The name inside the brackets has to match exactly, capitals and all. You stored "x" and asked for "X".
NameError: name 'x' is not defined You wrote box[x] without quotes, so Python went looking for a variable called x. Dict names are text: box["x"].
TypeError: update() takes 2 positional arguments but 5 were given The def line now takes the whole box, but the call still hands over four loose numbers. Both ends have to change together.
Only one box shows up screen.fill is still inside draw, wiping the window between every box.
The boxes leave a smear behind them The opposite — screen.fill has gone missing entirely, so nothing ever clears the last frame.
