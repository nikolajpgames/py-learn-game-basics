A Wall Of Bricks

Fifty bricks, in five neat rows. Typing out fifty positions by hand would be a bad evening — so a loop inside a loop does it.

What you're making

A wall of coloured bricks across the top of the screen, built by counting rows and columns.

The ball goes straight through them. That is Session 24's job.

New this session

A loop inside a loop walks a grid. The outer one counts rows, the inner one counts columns, and the inside runs once for every square: five rows of ten is fifty goes.

The two counters are not positions. row and col are just 0, 1, 2, 3… The screen wants pixels, so each one gets turned into a position by multiplying by the size of a brick plus the gap between them.

Which means the wall lays itself out. Change how big a brick is, or how far apart they sit, and every brick moves to suit — because not one of those positions is typed in anywhere.

Turn the knobs

BRICK_ROWS = 5How deep the wall is. Try 12 and the game becomes a long siege.
BRICK_COLS = 10How wide. The centring sum uses this, so it always stays in the middle.
BRICK_GAP = 6The space between them. At 0 it is a solid slab; at 30 it is a polka dot pattern with holes the ball can slip through.
BRICK_COLOURSA list of five colours, one per row. Add a sixth and nothing breaks — the % just wraps round at whatever length the list happens to be.

Stuck?

Hint 1 — how do row and col become x and y?

Each step across is one brick wide plus one gap: col * (BRICK_W + BRICK_GAP). Add where the wall starts and you have the x.

Down is the same sum with the other three names: row * (BRICK_H + BRICK_GAP), plus BRICK_TOP.

Column 0 gives 0 steps across, so the first brick sits exactly at the left edge of the wall. That is why counting from zero is convenient rather than annoying.

Hint 2 — what does the % do in the colour?

% gives the remainder after dividing. 7 % 5 is 2, because 7 divided by 5 is 1 with 2 left over.

So row % 5 counts 0, 1, 2, 3, 4, 0, 1, 2… — it wraps round. Which means the colours repeat however many rows you ask for, and nothing ever asks the list for an entry it does not have.

Hint 3 — where exactly does return go?
At the very end of the function, lined up with the bricks = [] at the start — not inside either loop. Put it inside the inner loop and it hands back after making one single brick.

def make_bricks():
    bricks = []
    left = (WIDTH - (BRICK_COLS * (BRICK_W + BRICK_GAP) - BRICK_GAP)) / 2

    for row in range(BRICK_ROWS):
        for col in range(BRICK_COLS):
            brick = {
                "x": left + col * (BRICK_W + BRICK_GAP),
                "y": BRICK_TOP + row * (BRICK_H + BRICK_GAP),
                "w": BRICK_W,
                "h": BRICK_H,
                "colour": BRICK_COLOURS[row % len(BRICK_COLOURS)],
            }
            bricks.append(brick)

    return bricks

Challenge

Leave holes in the wall. Skip a brick when the row and column agree on something — if (row + col) % 3 == 0: continue gives you diagonal stripes of gaps. continue means "skip the rest of this go and start the next one".

Try a few: row % 2 == col % 2 for a chequerboard, col < row for a staircase.

Then a pyramid. Make the number of columns depend on the row, and centre each row on its own. That one takes some thinking, and it is the same thinking as the pyramid in Session 4.

How it could break

Only one brick appears return bricks is inside one of the loops, so the function hands back after the first go. It belongs at the very end.
All fifty bricks are stacked in the same place The x and y are using fixed numbers rather than col and row. Every brick is being told to sit at the same spot.
They are in a diagonal line Both sums are using the same counter — probably row in both. Across uses col, down uses row.
IndexError: list index out of range BRICK_COLOURS[row] without the %, and there are more rows than colours.
The wall is off to the right The centring sum has lost its - BRICK_GAP, or the whole thing is not being divided by 2.
The bricks are drawn on top of the ball In draw, the brick loop comes after the ball. Whatever is drawn last ends up on top.

Stop while it still runs.
