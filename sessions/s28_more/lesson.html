More Levels

One level is a demo. Three is a game — and the only difference between them is two more text files and a counter.

What you're making

Three levels that follow one after another, a message when you clear one, and a win screen at the end.

And then as many more as you feel like drawing.

New this session

Nothing new. A number that remembers which level you are on, and an f-string that turns it into a filename.

Filenames can be built the same way as any other text. f"level{level:02}.txt" gives level01.txt, level02.txt and so on. The 02 means "pad it out to two digits with a zero".

And clearing the wall is a check you already know: if len(bricks) == 0. The only question is what happens next — another level, or the end.

Stuck?

Hint 1 — what does the :02 do?

Pads the number out to two digits with a zero in front. 1 becomes 01, 2 becomes 02, and 12 stays 12.

It goes inside the curly brackets after a colon: f"level{level:02}.txt".

The point is that files sort properly. Without it, level10.txt sorts before level2.txt, which looks like a computer being stupid and is actually alphabetical order doing its job.

Hint 2 — why make a new ball between levels?

Because the wall was cleared by a ball that is currently somewhere near the top of the screen going upwards at speed. Load the next level around it and it is instantly inside a brick.

ball = make_ball() puts it back above the bat, heading up, at the normal speed. One line, and the next level starts fairly.

Hint 3 — how does os.path.exists help?

It answers True or False for whether a file is there.

So instead of if level > 3 — a number you have to remember to change — you ask whether the next level file actually exists. If it does, load it. If not, they have finished.

Now the game finds out how long it is by looking, which means adding a level is just adding a file.

Challenge

Design a proper set. Six levels that get harder in a way you have thought about — not just more bricks, but shapes that make the ball behave differently. A funnel. A tunnel with one way in. A wall with a single gap.

Play each one and change it until it feels right. That is level design, and it is a completely different skill from programming — you cannot reason your way to it, you have to play it.

Then let somebody else play. Watch where they get stuck without saying anything. It is the most useful and most uncomfortable half hour in making games.

Keep the level files. The Geometry Dash arc uses the same trick, and by then you will have opinions about it.

How it could break

FileNotFoundError: level02.txt It does not exist yet, or the padding does not match the name — {level:02} looks for level02.txt, not level2.txt.
The game skips straight to the win screen The empty-wall check is running before any bricks were loaded, or the loader returned an empty list because the file has no hashes in it.
Level two starts with the ball already inside a brick ball = make_ball() is missing from the level change. See Hint 2.
It loops back to level one forever level is being reset somewhere it should not be — probably in the restart code, which should only run when the player presses R.
Winning and losing look identical render.py is only checking for one mode. It needs a separate message for "won".
NameError: name 'os' is not defined import os at the top of main.py, with the other imports.

Stop while it still runs. That is Arkanoid, with levels you drew yourself.
