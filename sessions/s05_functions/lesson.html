Your Own Words

This is how you stop writing the same lines over and over.

What you're making

Two words that don't exist in Python until you invent them — say_hello and double. Then a small experiment that shows something genuinely surprising about how they work.

You've been using other people's functions since Session 1. print is one. Now you get to write your own.

New this session

These are called functions, and they exist so you can write something once and use it over and over. You have been using other people's all along — print is a function, so is range. Today you write your own.

def invents a new word. Nothing happens when Python reads it — it just makes a note. The lines inside only run when you use the word later, and you can use it as many times as you like.

The thing in the brackets travels in. say_hello("Sam") sends the word Sam into the function, where it arrives under the name the def line gave it.

return sends an answer back out. double(7) hands you 14, which you can print or put in a box.

A function can still see the things made outside it. When you use a name, Python looks inside the function first — and if it is not there, it looks out into the file around it. That is how WIDTH and SPEED, set once at the top of a file, can be used deep inside a function further down.

And a function keeps its own private copies of things. That's the second diagram, and it's the bit that surprises people.

Stuck?

Hint 1 — why does nothing happen when I write a def?
Because def only invents the word, it doesn't use it. It's the difference between writing a recipe and cooking. To make it happen you have to write its name with brackets after it, further down: say_hello("Sam").
Hint 2 — function, or method?

Two words for almost the same thing, which is annoying but worth knowing.

A function stands on its own: print("hi"), double(7).

A method is a function that belongs to something, and you reach it with a dot: stars.append(star) is a method belonging to that list. You will meet those in Session 9.

Same idea either way — a named job you can run whenever you want.

Hint 3 — what's the difference between print and return?

print puts something on the screen for a human to read. That's all it does — the value is gone afterwards.

return hands a value back to whoever used the function, so it can be stored, printed, or used in a sum. double(double(5)) gives 20, because the inner answer got handed out and straight back in.

A function that prints is a dead end. A function that returns can be built on.

Hint 4 — why didn't score change?

When you call try_to_change(score), the function doesn't get the box — it gets a copy of what was in it, in a fresh box of its own that happens to share the name.

Setting that copy to 999 fills in the function's own box and leaves yours alone. When the function ends, its box is thrown away.

This sounds like a nuisance and is actually the point: a function can't secretly mess up the rest of your program. If you want an answer out, return it and catch it: score = try_to_change(score).

Hint 5 — reading is fine, changing is not

A function can happily read something from outside it. But the moment you assign to that name inside the function, Python decides the name is the function's own — and then complains that you used it before making it:

WIDTH = 800

def grow():
    WIDTH = WIDTH + 1   # UnboundLocalError

That is not a bug, it is a guard rail: it stops a function quietly rewriting things the rest of the program depends on.

The way round it is the one you already know — hand the value in, and return the new one back out. That is exactly why update() in the later sessions takes the position as arguments and returns it again, instead of reaching out and changing it.

Show me a finished version 
def triple(number):
    return number * 3


def shout(words):
    print(words.upper() + "!!!")


print(triple(5))
print(triple(triple(2)))

shout("we are ready for pygame")

How it could break

TypeError: say_hello() missing 1 required positional argument: 'name' You called it with empty brackets. The def line asks for one thing, so one thing has to go in: say_hello("Sam").
TypeError: say_hello() takes 1 positional argument but 2 were given The opposite — you handed it two things when it only has room for one. The brackets on the def line and the brackets where you use it must match.
NameError: name 'say_hello' is not defined Either a typo, or you're using it above the def. Python reads top to bottom, so the word has to be invented before it's used.
It prints None The function has no return, so it handed back nothing, and None is Python's word for nothing.
NameError: name 'answer' is not defined You're trying to use a variable outside the function that made it. It only exists in there — that's the diagram above.
Nothing happens at all You wrote the def but never used the word afterwards. Recipes don't cook themselves.
