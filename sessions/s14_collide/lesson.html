Session 14 Arc 2 · Motion & Time

When Boxes Meet

Your boxes notice walls. They do not notice each other — they slide straight through like ghosts. Today they stop doing that.

What you're making

Six big boxes drifting around, each one lighting up pink the moment it touches another.

This is the single most useful thing in any game. A ball hitting a bat, a player hitting a spike, a bullet hitting anything — all the same four questions.

New this session

Two boxes are touching only if they overlap across and down at the same time. Overlapping on just one of those is not touching at all — two boxes can sit in the same column of the screen and be miles apart vertically.

Which is four questions, and they are the same shape as your wall checks. Instead of asking "is this box past the edge of the screen?", you ask "is this box entirely past the edge of that other box?" four times. If the answer is no every time, they must be touching.

A function that answers yes or no like this is worth writing on its own, so you can use it anywhere. It hands back True or False — the same two values an if works on.

Stuck?

Hint 1 — how do I write one of the four checks?

Take them one at a time. This one asks "is box a entirely to the left of box b?"

if a["x"] + BOX_SIZE < b["x"]:
    return False

a["x"] + BOX_SIZE is a's right-hand edge, the same trick you used on the wall in Session 12. If that edge has not even reached b's left edge, there is no way they are touching, so you can stop right there.

The next three are the same sentence with the names swapped round, and then with y instead of x.

Hint 2 — why does it return False four times and True once?

Because it is much easier to prove two things are apart than to prove they are together.

Each check looks for one reason they cannot possibly be touching. Finding any one of them settles it, and return stops the function on the spot — the rest never run.

So if the function gets all the way to the bottom, every reason to say no has been ruled out. Whatever is left must be a yes.

Hint 3 — what does "a is not b" mean?

"These two names are not pointing at the same box."

Session 13 showed you that two names can be labels on one dict. The inner loop goes through every box, so sooner or later it reaches the same one the outer loop is holding — and a box always overlaps itself perfectly.

Without that check every box would light up pink permanently, which is at least an easy bug to spot.

Show me a finished version 
def overlaps(a, b):
    if a["x"] + BOX_SIZE < b["x"]:
        return False
    if b["x"] + BOX_SIZE < a["x"]:
        return False
    if a["y"] + BOX_SIZE < b["y"]:
        return False
    if b["y"] + BOX_SIZE < a["y"]:
        return False
    return True


# ... inside the game loop, after everything has moved

    for box in boxes:
        box["colour"] = BOX_COLOUR

    for a in boxes:
        for b in boxes:
            if a is not b and overlaps(a, b):
                a["colour"] = HIT_COLOUR

How it could break

Every box is pink, all the time The a is not b part is missing, so each box is finding itself. A box overlaps itself completely, every frame, forever.
Boxes go pink and stay pink Nothing sets them back to BOX_COLOUR at the start of the frame. Colour has to be worked out fresh each time, not remembered.
KeyError: 'colour' The colour was never put in the dict when the box was built. Every box needs all four — sorry, all five — of its keys from the start.
They only notice each other sometimes, at high speed Not your fault. At 2000 pixels a second a box can be fully left of another on one frame and fully right of it on the next, never overlapping on any frame you actually checked. Real games have this problem too. Slow them down.
Trying to make them bounce off each other, and they stick together juddering Worth knowing before you try: flipping both boxes' speeds when they touch does not work. They are still overlapping on the very next frame, so they flip back, and again, forever. Making things bounce off each other properly is a much bigger job than detecting the touch — and Pong does not need it, because a bat does not move when a ball hits it.
TypeError: overlaps() missing 1 required positional argument: 'b' It needs two boxes to compare. You have called it with one.

Stop while it still runs.
