Knock Them Out

The ball goes straight through fifty bricks as though they were not there. One overlaps call away from being a game.

What you're making

Bricks that vanish when the ball hits them, and a ball that turns round when it does.

It will be almost right. There is one thing wrong with it that you will see within a minute, and fixing that is next session.

New this session

Nothing new at all — this is Session 19 again. Check the moving thing against everything in a list, mark what got hit, then rebuild the list without them.

Mark first, clear afterwards. You cannot take bricks out of the list while you are looping through it. Session 18's picture explains why, and it has not stopped being true.

Turning the ball round is one line: flip vy. Which is right when the ball comes up from underneath, and wrong the rest of the time. Write it anyway — you will spot the problem faster by playing it than by reading about it.

Stuck?

Hint 1 — why one flip per frame rather than one per brick?

Because flipping twice puts it back where it started.

When the ball catches two bricks in the same frame — easily done at a corner — a flip inside the loop runs twice, vy ends up unchanged, and the ball ploughs on through the wall as though nothing happened.

So: find out whether anything was hit, then turn the ball round once.

Hint 2 — the ball sometimes goes through the wall sideways

Good. You have found the thing this session is deliberately leaving broken.

Flipping vy assumes the ball hit the top or the bottom of a brick. When it clips a brick's side, the right answer is to flip vx — and flipping vy instead sends it onwards through the wall, bouncing off nothing.

That is Session 25, and it is a better session because you have seen the problem first.

# main.py, after the ball has moved

    hit_one = False
    for brick in bricks:
        if overlaps(ball, brick):
            brick["gone"] = True
            hit_one = True

    if hit_one:
        ball["vy"] = -ball["vy"]

    kept = []
    for brick in bricks:
        if "gone" not in brick:
            kept.append(brick)
    bricks = kept

Challenge

Work out the rule before you are told it. Play until you catch the ball going through a brick's side, then think about what the code should have done instead.

You know the ball's position and size, and the brick's. From those four numbers on each, you can tell which edge the ball has only just crossed — and that is the edge it came in through.

Have a go at writing it. Then compare with Session 25, which does exactly that. Getting it yourself first is worth more than reading it.

How it could break

The ball goes through the wall sideways sometimes Expected. That is the bug this session leaves in on purpose — see Hint 2 and then Session 25.
Hitting two bricks at once sends the ball straight through The flip is inside the loop, so it happened twice and cancelled itself out. Move it outside, guarded by hit_one.
RuntimeError: dictionary changed size during iteration Something is being removed inside the checking loop. Mark first, clear afterwards.
Every brick disappears at once overlaps is returning True for everything — the comparisons are probably the wrong way round. Compare it against Session 19's.
The bricks come back The rebuilt list is not being put back into bricks. It needs bricks = kept at the end.
NameError: name 'overlaps' is not defined It lives in state.py, so main.py has to import it by name.

Stop while it still runs.
