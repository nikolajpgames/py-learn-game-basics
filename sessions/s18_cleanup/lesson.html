Cleaning Up

Every shot you have ever fired is still out there, somewhere above the screen, being moved and drawn sixty times a second. Time to let them go.

What you're making

The same game, except a shot stops existing once it leaves the top of the screen.

Nothing will look different. Fire two hundred shots and then compare how it feels — that is where you will see it.

New this session

Things need taking out of lists as well as putting in. Anything that spawns while a game runs eventually has to stop existing, or the list grows forever and the game slowly grinds.

The obvious way is a trap. Walking through a list and removing items from that same list as you go makes Python lose its place, and some items never get looked at. It is one of the most common bugs there is, and it does not crash — it just quietly gets it wrong.

So turn it round: build a list of the ones you want to keep. Go through the old list, put the survivors into a fresh one, and use that from then on. Nothing is removed from anything, so nothing can lose its place.

Stuck?

Hint 1 — what does "keep the ones you want" look like?

Three moves: an empty list before the loop, an append inside it for the survivors, and a return at the end.

def update_shots(shots, dt):
    kept = []

    for shot in shots:
        shot["y"] = shot["y"] - SHOT_SPEED * dt
        if shot["y"] + SHOT_H > 0:
            kept.append(shot)

    return kept

Exactly the same shape as building the stars in Session 9. The only difference is that this one runs every frame instead of once.

Hint 2 — why not just use remove?

There is a remove, and it does work — the trouble is only when you use it while looping over the same list, which is exactly when you want it.

Try it and see. Fire three shots close together so several go off the top at once, then use shots.remove(shot) inside the loop. Some will hang around for an extra frame or two before finally going, because they got skipped.

It never crashes and it looks nearly right, which is what makes it nasty. The picture above is what is actually happening.

Hint 3 — why "+ SHOT_H" in the check?
shot["y"] is the shot's top edge, so it goes below 0 while most of the shot is still visible. Adding its height gives you the bottom edge, and only when that passes 0 has the whole thing really gone. Same edge-thinking as the boxes and the walls.

def update_shots(shots, dt):

    for shot in shots:
        shot["y"] = shot["y"] - SHOT_SPEED * dt

        if shot["y"] + SHOT_H > 0:

Challenge

Give shots a lifetime instead of an edge. Put an "age" in each shot when it is made, add dt to it every frame, and throw the shot away once it gets past a second and a half.

Same pattern, different question. Now shots die of old age wherever they happen to be, which is how a lot of games handle bullets, sparks and explosions.

Try both together: gone if it leaves the screen or gets too old. Two reasons to drop something, one list of keepers.

How it could break

The number still never goes down main.py is not catching what the function hands back. It has to be shots = update_shots(shots, dt), with the shots = on the front.
TypeError: 'NoneType' object is not iterable update_shots has no return at the end, so it hands back nothing, and shots becomes nothing. Then drawing them falls over.
Every shot disappears the instant you fire it The check is the wrong way round, so it keeps the ones that have gone and throws away the ones on screen.
Shots vanish while still visible near the top The check is using shot["y"] > 0 rather than shot["y"] + SHOT_H > 0. See Hint 3.
The game stutters every time you fire The print is still in there. Writing to the terminal sixty times a second is genuinely slow.
A few shots hang around one frame too long You used remove inside the loop. That is the bug in the picture, in the wild.
