Two Hundred Stars

Last time a loop saved you writing the same draw line five times. This time one saves you writing the stars themselves.

What you're making

A proper night sky. Two hundred stars, scattered at random, none of them typed out by you.

Then you change one number to two thousand, and it costs you nothing.

New this session

A loop can build a list, not just walk through one. Start with an empty list, and each time round add one more thing to it. After two hundred goes you have two hundred stars, and you typed one.

.append(…) puts one thing on the end of a list. It is a method — a function that belongs to the list, which is why it is written with a dot after the list's name.

random.randint(0, 800) picks a whole number between 0 and 800, differently every time. That is what stops all two hundred stars landing on top of each other.

So this file ends up with two loops in it, doing two completely different jobs. They are easy to mix up, so the picture below keeps them apart.

Stuck?

Hint 1 — what does range(200) actually give me?
The numbers 0, 1, 2, all the way up to 199. That is two hundred numbers, but it stops before 200 — same as Session 4. Here you do not even use i; the loop is only there to count out two hundred goes.
Hint 2 — where exactly does the building loop go?

Above running = True, not inside the game loop. It needs to have finished before the drawing starts.

Line the left edges up: stars = [] and for i in range(…) both sit hard against the left margin, and the four lines that build each star are pushed in under the for.

Hint 3 — why does append go on the list and not on its own?
append belongs to the list, so you say which list first: stars.append(star). Written on its own, Python has no idea what you want to append to. That dot is doing real work.
Show me a finished version 
# above the game loop

stars = []

for i in range(STAR_COUNT):
    x = random.randint(0, WIDTH)
    y = random.randint(0, HEIGHT)
    star = (x, y)
    stars.append(star)

Challenge

Put the building loop in the wrong place on purpose. Move the whole block — stars = [] and everything under it — down inside the game loop, indented to match. Run it.

Work out why it does that before you move it back. The answer is written on the diagram further up this page, and once you have said it out loud you will understand what a frame is.

How it could break

NameError: name 'random' is not defined import random is missing from the top of the file. It is a separate import from pygame.
AttributeError: 'tuple' object has no attribute 'append' You are appending to the wrong thing. Only the list grows — stars.append(…), never star.append(…). One letter, completely different object.
IndentationError: expected an indented block The four lines that build a star have to be pushed in under the for. That indent is what puts them inside the loop.
Only one star appears stars.append(star) is not indented, so it runs once after the loop has finished — adding only the last star made.
All the stars sit in one vertical line You used randint for y but left a fixed number for x, so every star got the same across-position.
The window takes ages to open Not broken. STAR_COUNT is enormous and it is genuinely making all of them, one at a time, before the window can appear.

Stop while it still runs.
