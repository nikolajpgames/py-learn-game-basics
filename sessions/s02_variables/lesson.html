Boxes With Names

Printing the same words every time gets dull fast. Now the computer gets somewhere to keep things.

What you're making

A tiny scoreboard. A name, a score and a number of lives — which then change, and print differently the second time.

Every game you've played is doing this constantly. Your score is a box, and something keeps putting bigger numbers in it.

New this session

A variable is a name with something kept inside it. score = 0 makes a box called score and puts 0 in it. From then on, writing score means "whatever is in that box right now".

The = sign is not maths. It doesn't mean "is equal to", it means put this in that box. Which is why score = score + 100 makes sense: work out what's in the box, add 100, put the answer back.

A box can hold four kinds of thing. Text like "Sam" (its proper name is a string). Whole numbers like 7 (an integer). Decimals like 3.5 (a float). And yes-or-no values, True and False (a boolean). The picture below has all four.

Text and numbers behave differently. "3" with quotes is a character. 3 without them is a number you can do sums with. They look the same and are not.

Stuck?

Hint 1 — why does score = score + 100 work?

Read it right-to-left, not as maths. The right-hand side is worked out first: whatever is in score, plus 100. Then the answer is dropped back into the box on the left.

So if score was 0, the right-hand side works out to 100, and 100 goes into the box. As maths it would be nonsense. As an instruction it's perfectly clear.

Hint 2 — what's the difference between 3 and "3"?

3 is a number. You can double it, add to it, compare it.

"3" is a character, the same as "a" or "?". It just happens to look like a number.

3 + 3 gives 6. But "3" + "3" gives "33", because gluing two lots of text together is what + means for words. This catches people out for years.

Hint 3 — what is the f in front of the quotes?
Short for format. It tells Python "there are boxes hidden in this sentence, look for the curly brackets". Without the f, "{name}" just prints the characters {name}, which is a good way to check you actually typed it.

Challenge

Build a character sheet. Pick a character from a game you like and give them boxes: health, attack, speed, a name, whatever fits.

Then have them take a hit — knock the health down, print the sheet again. If you want to push it, work the damage out from the numbers rather than typing it in: health = health - attack.

How it could break

NameError: name 'levl' is not defined A box by that name has never been made — almost always a typo. Python is fussy about spelling and won't guess.
TypeError: unsupported operand type(s) for -: 'str' and 'int' str means text and int means whole number. You're trying to subtract a number from some words, which is what happens if a number accidentally has quotes around it.
SyntaxError: cannot assign to literal You've written it backwards: 100 = score. The box always goes on the left of the =.
It prints {name} instead of the name The f is missing from in front of the opening quote.
The number doesn't change You worked out score + 100 but never put the answer anywhere. It needs to be score = score + 100.
