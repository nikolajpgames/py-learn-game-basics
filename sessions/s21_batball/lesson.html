Bat And Ball

A new game, and almost nothing in it is new. The bat is your ship with a different name, and the ball is the bouncer from Session 12.

What you're making

A bat you steer along the bottom and a ball that bounces off the two walls and the ceiling — and falls straight past you if you miss.

Everything here you have written before. See how fast it goes the second time.

New this session

Nothing, really. This is the first session with no new idea in it at all. The bat is Session 16's ship, the ball is Session 12's bouncing box, and the four files are Session 15's shape.

What is worth noticing is how little of it you have to think about. Bouncing off a wall used to be a whole session. Today it is four lines you can write from memory while talking to somebody.

The one change: the ball bounces off the left, right and top walls, but not the bottom. Falling off the bottom is the whole point of the game.

BAT_SPEED = 520How fast you can move. Lower than the ball and the game becomes unfair rather than hard.
BAT_W = 110Try 400 for something you cannot miss with, then 20 for something you always will.
BAT_YHow far up from the bottom the bat sits. More room below means more time to react after a miss — except nothing is watching for a miss yet.

Stuck?

Hint 1 — what should the ball's dict have in it?

Six things: x and y for where it is, w and h for how big it is, and vx and vy for which way it is going.

The w and h are there because overlaps will want them shortly, exactly as the shots and targets needed them in Session 19.

Hint 2 — how do I bounce off only three walls?

Write the four checks you know, then delete the one for the bottom.

if ball["x"] < 0:
    ball["x"] = 0
    ball["vx"] = -ball["vx"]

The ball["x"] = 0 line puts it back against the wall before turning it round. That is the fix from Session 15's challenge, and it stops the ball juddering along the edge.

def make_ball():
    ball = {
        "x": WIDTH / 2 - BALL_SIZE / 2,
        "y": BAT_Y - 120,
        "w": BALL_SIZE,
        "h": BALL_SIZE,
        "vx": BALL_SPEED,
        "vy": -BALL_SPEED,
    }
    return ball


def update_ball(ball, dt):
    ball["x"] = ball["x"] + ball["vx"] * dt
    ball["y"] = ball["y"] + ball["vy"] * dt

    if ball["x"] < 0:
        ball["x"] = 0
        ball["vx"] = -ball["vx"]
    if ball["x"] + ball["w"] > WIDTH:
        ball["x"] = WIDTH - ball["w"]
        ball["vx"] = -ball["vx"]
    if ball["y"] < 0:
        ball["y"] = 0
        ball["vy"] = -ball["vy"]

Challenge

Make the ball leave a trail. Keep a list of the last twenty places it has been. Each frame, add where it is now to the end and drop the oldest off the front — the keep-the-ones-you-want pattern from Session 18, with a length limit instead of an edge.

Then draw them all, oldest first, in dimmer and dimmer colours. Two lines of maths and it looks like a comet.

It is worth doing now because you will want exactly this for the cube trail in the Geometry Dash arc, and it is easier to work out on something that only has one of them.

How it could break

The ball goes through the wall and never comes back The bounce check flips the speed but does not put the ball back against the wall, so it is still outside on the next frame, flips again, and shivers its way out. Add the ball["x"] = 0 line.
The ball bounces off the bottom too You wrote all four checks. Delete the one for the bottom — missing has to be possible.
NameError: name 'ball' is not defined It is made inside the loop, or below the line that uses it. It belongs above running = True, made once.
TypeError: draw() takes 2 positional arguments but 3 were given draw in render.py needs a slot for the ball as well as the bat.
The ball goes so fast it passes through walls At very high BALL_SPEED it can be fully left of the wall on one frame and fully right on the next. Real games have this problem too. Slow it down.
