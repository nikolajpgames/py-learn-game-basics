Session 20 Arc 3 · Shooter

Score And Game Over

You can shoot things. Nothing counts, nothing ends, and nothing tells you how you did. Those three things are the difference between a toy and a game.

What you're making

A score in the corner that goes up when you hit something, a game that ends when you clear the screen, and a key that starts it again.

By the end of this you have a complete game. Somebody else could sit down and play it without you explaining anything.

New this session

Drawing words takes two steps. First you make a font — once, before the loop, because it is slow. Then every frame you ask it to turn some text into a little picture, and paste that picture onto the screen with blit.

blit just means "stick this picture there". It is how everything that is not a plain rectangle gets drawn, and it is the same call you will use for real sprites later.

And a game needs to know what it is currently doing. One variable — mode — holding either "playing" or "over". The loop looks at it and decides what to update and what to draw. That is a state machine, and it is how every menu, pause screen and death screen ever made works.

Stuck?

Hint 1 — why is the font made outside the loop?

Because building a font means loading and measuring a whole alphabet, and that is slow. Doing it sixty times a second would cost more than everything else in the game put together.

font.render is the cheap part, and that does belong in the loop, because the score changes.

Same rule as the stars in Session 9: make the expensive thing once, up front; use it every frame.

Hint 2 — what is blit?

Copying one picture onto another. font.render hands you a small picture of your words, and screen.blit(img, (12, 10)) stamps it onto the screen with its top-left corner at that spot.

pygame.draw.rect paints a shape; blit pastes a picture. When you swap the rectangles for real artwork, every one of them becomes a blit.

Hint 3 — how do I put the text in the middle?

The picture knows its own size, so ask it and take off half:

img = font.render("ALL CLEAR - PRESS R", True, TEXT_COLOUR)
x = WIDTH / 2 - img.get_width() / 2
y = HEIGHT / 2 - img.get_height() / 2
screen.blit(img, (x, y))

Exactly the same half-the-width trick as centring a shot on the ship.

# render.py

pygame.font.init()
font = pygame.font.Font(None, TEXT_SIZE)


def draw(screen, stars, ship, shots, targets, score, mode):
    ...                                  # everything you already had

    img = font.render(f"SCORE {score}", True, TEXT_COLOUR)
    screen.blit(img, (12, 10))

    if mode == "over":
        img = font.render("ALL CLEAR - PRESS R", True, TEXT_COLOUR)
        screen.blit(img, (WIDTH / 2 - img.get_width() / 2,

Challenge

Make it possible to lose. Give the targets a slow downward drift, and add a third mode — "dead" — for when one of them reaches the ship. The ship has an x, a y, and now needs a w and an h, and then overlaps works on it like anything else.

Two ways to finish, two different messages. Winning and losing should not look the same.

Then a proper front screen: start in a "title" mode that shows the name of the game and waits for a key. Three modes and the game has a beginning, a middle and an end.

Keep a best score across restarts while you are at it. It only has to be a variable that the restart does not reset — which is a nice little puzzle in itself.

How it could break

pygame.error: font not initialized The pygame.font.init() line is missing from the top of render.py. Python runs that whole file the moment main.py imports it, which is several lines before pygame.init() — so the font machinery has to be started up there and then.
The score never changes score = score + 1 is inside a function somewhere, so it is changing a copy. Numbers travel as copies — the counting has to happen in main.py, where the real score lives.
The score jumps up by ten at a time One shot is overlapping a target for several frames before either gets cleared, or one shot is hitting more than one target. Check the clear-out loops actually run every frame.
Everything freezes and R does nothing The restart is inside if mode == "playing":, so it can never run once the mode is "over". It belongs in the event loop, outside that check.
TypeError: draw() takes 5 positional arguments but 7 were given draw needs slots for score and mode as well. Both ends together.
The game-over text is off to the left You used WIDTH / 2 without taking off half the picture's width. img.get_width() asks it how wide it turned out.

Stop while it still runs. That is a whole game.
