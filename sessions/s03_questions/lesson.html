Asking Questions

Up to now the computer has done every line, every time. Now it gets to choose.

What you're making

A program that reacts. High score? Say well done. No lives left? Game over. Same file, different output depending on the numbers.

The bouncing box in Session 12 is four of these questions, one after another.

New this session

if asks a question, and the lines underneath only run when the answer is yes. else covers the no.

The indent is what decides which lines belong to the question. Most languages use curly brackets for this. Python uses spaces, which are invisible — so the shape of your code isn't decoration, it's the actual meaning.

Push a line in by four spaces and it's inside. Leave it against the left edge and it always runs.

Stuck?

Hint 1 — why is it == and not = ?

They're two completely different jobs that unfortunately look alike.

= means put this in that box. score = 100 changes the score.

== means is this the same as that? score == 100 changes nothing and just answers yes or no.

Getting them the wrong way round is a rite of passage. Everyone does it, forever.

Hint 2 — how many spaces should I use?
Four. It doesn't strictly have to be four, but everyone uses four and being consistent is what actually matters — mixing four and three in the same block is an error. Your editor's Tab key will usually do four for you.
Hint 3 — what is True and False?

A question's answer. Put print(score > 100) in your file and run it — you'll get True or False printed out, nothing else.

That's all if is doing: working the question out to True or False, then running the indented lines if it was True. Both need a capital letter.

Hint 4 — does indenting hide a variable?

No — and this one catches out people who have used other languages.

Indenting groups lines so Python knows which belong to the question. It does not build a private room. Anything made inside an if is still there afterwards:

if score > 100:
    message = "well done"

print(message)   # works fine, it is still here

The same goes for for and while. In Python only a function makes a private area, and that is Session 5.

Show me a finished version 
score = 150
lives = 2

if score > 100:
    print("High score!")

if lives > 0:
    print("Still alive.")
else:
    print("Game over.")

print("Thanks for playing.")

Challenge

Make it ask you a question. Add this line near the top:

answer = input("What is 6 times 7? ")

Then check it with if answer == "42": and print something different for right and wrong. Careful — input always hands back words, never a number, so the 42 needs its quotes.

Get that working and you've written a quiz. Add three more questions and a score that goes up.

How it could break

IndentationError: expected an indented block You wrote an if line but the line under it isn't pushed in. An if has to have something inside it.
IndentationError: unindent does not match any outer indentation level The indents are inconsistent — four spaces on one line, three or five on the next. Line the left edges up exactly.
SyntaxError: expected ':' The colon on the end of the if line is missing. if score > 100 needs to be if score > 100:
SyntaxError: invalid syntax. Maybe you meant '==' instead of '='? Python has guessed correctly — you wrote one equals sign in a question. It wants two.
TypeError: '>' not supported between instances of 'str' and 'int' You're comparing words to a number. If it came from input, it's words — compare it against "100" with quotes, or convert it with int(answer).
A line runs when it shouldn't It isn't indented, so it was never inside the question. Look at the left edge, not the words.
