The Bat Hits Back

The ball ignores your bat completely. Fixing that is easy. Making it feel good takes one more line, and that line is the whole game.

What you're making

A ball that bounces off the bat — and comes off at a different angle depending on where along the bat it landed.

Without the angle you have a game you cannot steer. With it you can aim.

New this session

Bouncing off the bat is overlaps plus flipping vy. You have written both before. That part is five minutes.

But you have to check the ball is going down first. Otherwise a ball that is already inside the bat flips every frame and sticks there, buzzing. One if stops it: no bouncing unless vy is positive.

And then the important line. Rather than sending the ball straight back, work out how far from the middle of the bat it hit, and use that to set vx. Hit the middle and it goes straight up. Hit the left end and it comes off hard to the left.

That one line is the difference between watching a ball and playing a game. It is how every bat-and-ball game since 1976 has worked.

Turn the knobs

BAT_W = 110Changes both how easy it is to hit and how sharply you can aim — the sums use the bat's own width, so a wide bat gives gentler control.
BALL_SPEED = 340Now sets the sideways speed as well as the up-and-down. Turn it up and everything gets faster together.
hit / (bat["w"] / 2)Try dividing by bat["w"] / 4 instead. Now only the middle half of the bat gives you any control and the ends fire it off sideways.
ball["vy"] < 0Take this check out and watch what happens when the ball catches the bat's edge. Put it back.

Stuck?

Hint 1 — why check that the ball is going down?

Because overlaps is true for several frames in a row while the ball is passing through the bat.

Without the check: frame one it overlaps, so flip — now it is heading up. Frame two it is still overlapping, so flip again — heading down. It buzzes inside the bat instead of bouncing off it.

Only bouncing when it is heading down means the flip can only happen once, because straight afterwards it is heading up.

Hint 2 — what is that hit sum actually doing?

Measuring, then scaling.

(ball's middle) - (bat's middle) gives you a distance in pixels: 0 dead centre, about −55 at the far left of a 110-wide bat, about 55 at the far right.

Dividing by half the bat's width squashes that into roughly −1 to 1, no matter how wide the bat is. Multiplying by BALL_SPEED turns that fraction into an actual sideways speed.

Hint 3 — why move the ball to the top of the bat?
Because it has usually sunk a few pixels in before you noticed. Setting ball["y"] = bat["y"] - ball["h"] lifts it back so its bottom is exactly resting on the bat's top, and then it leaves cleanly. Same idea as putting a bouncing box back against the wall.

def bounce_off_bat(ball, bat):
    # only when the ball is heading downwards, or it sticks
    if ball["vy"] < 0:
        return

    if not overlaps(ball, bat):
        return

    ball["y"] = bat["y"] - ball["h"]
    ball["vy"] = -ball["vy"]

    hit = (ball["x"] + ball["w"] / 2) - (bat["x"] + bat["w"] / 2)
    ball["vx"] = (hit / (bat["w"] / 2)) * BALL_SPEED

Challenge

Make the ball speed up. Every time it hits the bat, multiply both speeds by 1.02. A rally that goes on gets steadily more frightening, which is how the arcade ones kept your money.

You will need a ceiling on it or it eventually goes through walls. Stop it climbing past about three times where it started.

Then make the bat shrink by a few pixels each time too. Nothing in the aiming sums breaks when you do, because every one of them uses bat["w"] rather than the number 110.

How it could break

The ball sticks to the bat and buzzes The if ball["vy"] < 0: return check is missing, so it flips on every frame it is touching.
The ball goes straight up and down forever and you cannot get out of it You are hitting the exact middle of the bat every time, which asks for vx of exactly 0 — the aiming working perfectly. Move the bat a little as you hit it.
The ball passes through the bat when moving fast In one frame it went from above the bat to below it without ever overlapping. Slow the ball down, or make the bat taller.
NameError: name 'overlaps' is not defined It needs to be in state.py and imported into main.py if you call it there.
The ball bounces off the bat's sides as well as its top That is what overlaps honestly reports — it does not know which side. It rarely matters for a bat, and it very much will matter for bricks, which is Session 25.
The ball bounces but always at the same angle The hit lines are missing, or vx is being set before vy is flipped. Order does not matter for these two, but both have to be there.

Stop while it still runs.
